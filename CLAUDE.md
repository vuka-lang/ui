# vuka ui — guide for coding agents

The component and page runtime of the vuka set: nodes, states, the render
tree, the live machinery (`live/`), and the kit components. Releases on one
version with vuka, web, orm and flow.

## Design philosophy

- **No new type, keyword or annotation unless necessary.** Prefer
  inference, an existing convention, or classification by use; a
  declaration is reserved for trust boundaries (`ui.State` = declared
  client writability — infer what costs performance, declare what costs
  safety). Precedents: the one-state merge (no `@ui.Local`/`@ui.Derived`,
  `ui.Assign` retired), §5 fallthrough (declarations deleted, not added),
  `ui.Dialog` rejected for `ui.State[*T]` + the kit Modal.
- **Frontend-framework writing feel.** Match the spelling a Vue/React/
  Svelte developer expects, then make it compile-time-checked where those
  frameworks fail at runtime. Check what already exists before adding:
  `ui.Teleport`, `ui.Await`/`@ui.Defer`, `ui.Lazy`, slot fallbacks
  (`ui.SlotOr`) are all already here.
- The design ledger is `docs/rfc/components-seamless.md` in the vuka repo
  — amend it before building.

## Repo facts

- `*_html.go` files are generated by the vuka compiler pinned in
  `tools.mod` — regenerate with `go generate ./...` (must produce no
  diff in CI); a kit change needing a newer compiler waits for that
  compiler's release.
- Keep third-party dependencies at ~zero (`x/net` for the sanitizer is
  the exception); prefer the stdlib.
- vukavet must stay clean; CI runs race tests and the fuzz targets
  (`FuzzTreePatch`) — new tree/patch logic gets fuzz coverage.
- Stable ids (live ids, `ui.AutoID`) derive from key paths / call sites,
  never from allocation counters — partial re-renders must not shift them.

## House rules

- Same-named branches across the vuka-lang repos are swapped into each
  other's CI builds — coordinate cross-repo changes by branch name.
- Never use `git stash` (shared stash list); work in worktrees under
  `.claude/worktrees/`.
- Generic domains only (users, orders, Button, Card) in code, tests,
  commits and PRs — never a downstream app's or customer's name.
- Never wipe the Go module cache. Tag or release only on the owner's
  explicit order.
